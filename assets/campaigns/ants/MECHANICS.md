# 《全巢之力》机制设计

> 设计原则：**确定性代码管状态，模型只管生成**。
> 本文档的每一条机制，都标注了它在运行时里的落点——**默认零代码改动**，仅「经文」一节给出一个可选补丁，让 AI 的记账直接产出"被记歪的经文"。

---

## 一、玩家、视角与输入

玩家扮演的不是神，是一个下班回家的普通人。第一人称，输入的是动作、对话、念头。**神没有技能栏、没有属性面板、没有"神力值"**——他唯一的"能力"就是随手，而随手会造成后果。这一点必须在 UI 与文本里贯彻：任何让玩家感觉自己在"操作一个神"的设计都是错的。

运行时落点：`card-ants.json` 的叙述者卡 + `first_mes` 序章；`intro.md` 为剧本存档。

---

## 二、状态变量（全部存在记忆账本里）

运行时已有五个账本分区 `characters / items / relations / plots / notes`（`src/harness/memory-ledger.ts`）。本作把游戏状态挂成固定 key 的 `notes` 条目，**不改代码**。玩家用 `/state` 查看。

| 状态 | 账本 key | 取值 | 谁在改 | 说明 |
| --- | --- | --- | --- | --- |
| 信仰度 | `sys-faith` | 0-100 | 叙述者/记账员 | 维尔派的虔诚程度。>70 触发献祭与圣战；<30 教派开始分裂 |
| 巢群规模 | `sys-colony` | 繁荣 / 稳定 / 凋敝 / 灭绝 | 叙述者/记账员 | 由玩家行为直接决定（糖＝繁荣，战争/开水＝凋敝/灭绝） |
| 怀疑度 | `sys-doubt` | 0-100 | 叙述者/记账员 | 逆的影响力。高＝教会摇摇欲坠，但巢活得更久 |
| 世代 | `sys-generation` | 整数 | 叙述者 | 每幕至少 +1，时间跳跃即 +1 |
| 经文条目 | `scripture-N`（N 递增） | 文本 | **记账员（见第四节）** | 一条"蚂蚁如何记载神做过的事"，允许记歪 |
| 神迹清单 | `miracle-N`（N 递增） | 文本 | 叙述者 | 玩家做过、被蚂蚁命名的事：天罚 / 赐食 / 神之泪 / 神弃我们而去 |
| 派系影响力 | `sys-factions` | 四个数（女王/维尔/灰烬/逆） | 叙述者 | 每次神谕或显灵后按各方解读此消彼长 |

**关键约束**：这些状态由旁侧模型从剧情正文里抽取，**不由玩家直接改**。玩家想让信仰降下来，只能通过剧情行为（比如当众否定经文），不能"点按钮"。

## 三、主线推进（已有代码，直接用）

运行时 `director/` 已实现：`arc.json` 的 `phases` 数组按 `unlockKeywords` 命中 + `minTurns` 门槛推进，每回合把 `【主线·第 N 幕】当前目标 / 剧情方向 / 本幕基调 / 本幕必发生` 注入 system（`Director.buildDirective()`）。

本作六幕的 `unlockKeywords`、`mustEvents`、`eventHint`、`mood`、`tension` 全部写在 `arc.json`。**第一至五幕的 `mustEvents` 是原著锚点，玩家可以改细节，但事件本身必须按序发生**；第六幕无锚点，正典由玩家的终局选择决定。

---

## 四、经文机制（本作签名机制）

**一句话**：蚂蚁如何记载神做过的事，与神实际做了什么，永远是两回事；而玩家可以亲眼看到自己被记成了什么。

### 4.1 默认实现（零代码改动）

叙述者卡里已写死「经文规则」：每幕至少产出一条新的经文条目，并在叙事中如实呈现它的走样。条目落进账本的 `plots` / `notes`，玩家 `/state` 可见。

### 4.2 完整实现（推荐，可选补丁）

要让经文**由旁侧模型自动、每回合、结构化地**产出，只需把记账员的 system prompt 换成"经文模式"。改动点：`src/harness/memory-ledger.ts` 的 `SCRIBE_SYSTEM` 常量，在它的 `notes` 段语义后追加下面这段：

```
【经文模式·本战役专用】除了上面的账本，你还要额外输出一段"经文"：
把本轮神的举动翻译成蚁群的语言，写入 notes，key 用 scripture-<自增序号>，
content 用 {"as":神实际做了什么, "recorded":蚂蚁们如何记载它, "drift":记歪在哪里}。
要求：recorded 必须与 as 有可辨识的偏差，且偏差方向要符合当前势力——
维尔派记为恩典与深意、女王派记为资源与代价、灰烬派记为号召、逆记为祸根。
绝不让 recorded 等于 as。
```

补丁后的收益：玩家每回合都能打开账本，读到一条刚出炉的、把自己好心记成暴行的"经文"——这是整部作品里 AI 价值最集中、也最难被写死脚本替代的一处。

### 4.3 世代漂移

每 `sys-generation` +1，叙述者须回头**改写一条旧经文**，使其离真相更远（口耳相传的失真）。玩家如果复看早期条目，会发现自己记忆里的事，和经文里的事，已经不是同一件了。

## 五、神谕卡机制（复用 decision-card）

运行时 `harness/decision-card.ts` 已提供：模型在重大转折调用 `decide` 工具，弹出 2-4 个候选方向 + 允许自由输入，选择写入 `decisions.jsonl` 留痕。本作改称"神谕"。

**触发时机**（只在两种情形，其余一律靠自由输入）：
1. 请求超出"随手可做"的范围（提米的无解之愿、断颚的请令、灰烬的献身）；
2. 一次显灵是"落下去"还是"收回来"，会不可逆地改变巢群命运。

**神谕卡选项的生成提示**（写进叙述者卡，已含）：
- 应允（按字面实现）
- 沉默（什么都不做，让时间处理）
- 敷衍（给一个自己都不信的回应）
- 用神的方式解决（最省事、最暴力的那种）

**无中立神谕**：神谕一旦落下，四个派系必须各自解读并各记一条经文——同一句"我不管了"，维尔记为"神在试炼我们"，女王记为"上面那位撤资了"，灰烬记为"神厌弃我们，故当自焚以谢"，逆记为"看吧"。

## 六、掷骰机制（复用 roll-card）

运行时 `harness/roll-card.ts` 把检定交给用户真随机，模型不得擅改。本作用在**神的物理后果**上：

- 你走得急 → 对蚁巢是一场几级地震？（掷骰）
- 你抖了下烟灰 / 打了个喷嚏 → 有多少巢室塌方？
- 你倒水时水流偏了几度 → 哪些支道被淹？

**意义**：把"神并不掌控自己的破坏力"这件事变成机制。玩家不是故意作恶，只是没有精确控制——这也正是原著"毕竟……为什么不呢？"那种轻慢的物理基础。

---

## 七、尺度机制

`worldbook.json` 第一条（`constant: true`）是强制性换算表。叙述者每回合都看得到，须保证：**凡神与蚁同框，570 倍落差在文字里可感**。反向也成立——蚂蚁的一切宏图（山一样高的糖、几代人的战争）在神的视角里只是台阶上的一点白光。这一条同时是笑点引擎和恐怖引擎。

---

## 八、教派系统

四派共存，用 `sys-factions` 记录影响力（女王/维尔/灰烬/逆 四项，和为 100）。规则：

| 派系 | 主张 | 上升时 | 下降时 |
| --- | --- | --- | --- |
| 女王派 | 神＝可预测的天气 | 巢群扩张、寿命延长 | 粮荒、被神迹反噬 |
| 维尔派 | 神＝人格化的至高存在 | 玩家回应显灵 | 玩家长期沉默 |
| 灰烬派 | 神＝要喂饱的对象 | 玩家任何形式的回应（含沉默） | 玩家明确制止 |
| 不许愿者 | 神＝一桩算不平的交易 | 每一次应允后出现伤亡 | 玩家连续两次"应允且无代价" |

第三幕与第四幕之间，灰烬派应升至峰顶——那是玩家亲手把它喂大的。

## 九、AI 使用点清单

| 环节 | 谁生成 | 为什么必须由 AI 生成、写死就废 |
| --- | --- | --- |
| 蚂蚁的祈祷词 | 模型 | 每只蚂蚁的私心、误解、派系立场都不同，写死十几条立刻被玩家识破 |
| **经文条目** | **旁侧模型** | **玩家的每个行为都要被"翻译"成神学语言，且允许记歪——这是本作唯一的对手 AI** |
| 神谕卡选项 | 模型 | 选项必须贴着当下的具体情境长出来 |
| 各派系对同一神谕的解读 | 模型 | 同一个事实的四种解读，是一次真实的"观点对撞" |
| NPC 对话 | 模型 | 维尔/蚁后/提米/逆等六种声音，靠 roleplay 卡驱动 |
| 结局文本 | 模型 | 终局由玩家过往所有选择的组合决定，无法穷举 |

**AI 在这款作品里不是聊天框装饰**：它是全体 NPC + 唯一的对手 + 结局的合著者。

## 十、与运行时模块的对应表

| 本作机制 | 运行时模块 | 是否需要改代码 |
| --- | --- | --- |
| 叙述者与全部蚂蚁 | `roleplay/character-card.ts` + `assemble.ts` | 否（换卡即可） |
| 世界设定与尺度表 | `roleplay/lorebook.ts`（关键词 + 向量召回） | 否（换 worldbook.json） |
| 六幕主线与锚点 | `director/director.ts` + `arc.json` | 否 |
| 状态变量（信仰/巢群/怀疑/派系） | `harness/memory-ledger.ts`（notes 固定 key） | 否 |
| **经文记歪** | `harness/memory-ledger.ts` 的 `SCRIBE_SYSTEM` | **可选补丁（见 4.2）** |
| 神谕卡 | `harness/decision-card.ts` | 否 |
| 物理后果掷骰 | `harness/roll-card.ts` | 否 |
| 前情提要与世代压缩 | `harness/context.ts` | 否 |
| 存档 / 回档 / 世界线 | `harness/worldline.ts` + `store.ts` | 否 |
| 多 provider 兜底、记账分级 | `llm/client.ts` + `config.ts` | 否 |

**结论**：整套机制**默认零代码改动**即可跑；只有"经文自动记歪"这一条需要一处常量补丁。

## 十一、启动

```bash
# Git Bash
WANGDACHUI_CAMPAIGN=ants npm run web
# Windows PowerShell
$env:WANGDACHUI_CAMPAIGN="ants"; npm run web
```

打开 http://127.0.0.1:7620 。斜杠命令：`/state` 看账本（含经文与状态变量）· `/phase` 看幕进度 · `/snap` 存档 · `/back` 回档 · `/lore 词` 查世界书。
