# 《全巢之力》产品计划书

> **赛道**：🎮 跨次元游乐场（AI 游戏与互动叙事）
> **可运行 Demo**：https://quanchaozhili.vercel.app
> **开源仓库**：https://github.com/wangchi2068/quanchaozhili
> **一句话**：把一个知乎高赞回答，做成一场「你不知道自己被信过」的互动叙事。

---

## 一、这是什么

你叫张亮。你是一个刚下班、拎着外卖回家、鞋底黏着口香糖的普通人。

你家门口台阶的砖缝里，有一窝蚂蚁。它们用亮晶晶的粉末画了一个圆阵，用身体拼出了你的名字「张亮」——**缺了最后一笔**。智力最高的那几只学会了发声，正伏在笔画前，集体诵念你的名。

你蹲下来看了十几分钟，拍了照发朋友圈，准备起身离开。这时它们拼尽全力开口：

> 「全宇宙最尊贵、最仁慈的存在，请不要走。」

**这个游戏的主角不是神，是「被信过」这件事本身。**

改编自知乎答主 **@狐狸** 的高赞回答《克苏鲁可以被卑微的人类召唤，那人类可以被蚂蚁召唤吗？》
（https://www.zhihu.com/question/621853865/answer/3263972389 ，65541 赞）
第 1–5 幕忠于原著情节，第 6 幕为 AI 演绎补完。

---

## 二、为什么这件事必须由 AI 来做（对应「AI 场景价值」40%）

这是本作设计的核心判断：**我们不做一个"能聊天的游戏"，我们做一个"只有 AI 能做出来的游戏"。**

### 2.1 游戏的签名机制是「经文」——它天生需要一个会撒谎的叙述者

**蚂蚁如何记载神做过的事，与神实际做了什么，永远是两回事。**

你在台阶上顺手踩死一只兵蚁。伊甸园里发生的事是：你鞋底落下，0.3 秒，你甚至没低头。

而蚁巢的经文里发生的事是：**「神降下雷霆，诛灭僭越者。」**

这个错位不是文案上的花活，它是一个**结构化的机制**：每个回合，旁侧记账模型把你做过的事翻译成蚁群的神学语言，写入账本：

```json
{ "key": "经文·天罚篇",
  "desc": "神实际做了：随手踩死了一只兵蚁 ／ 蚁群记为：神降下天罚，诛灭邻巢僭越者 ／ 记歪在：把一次无意的踩踏记成了宗教裁决",
  "status": "已记载" }
```

**玩家可以随时打开账本，读到一条刚出炉的、把自己随手记成神迹的经文。** 而随着世代推移（蚁的世代以周计），旧经文还会被进一步改写——你翻回前三幕的条目，会发现它已经不是同一件事了。

**为什么写死就废**：歪解的方向取决于当前话语权最大的派系（维尔派记为恩典、女王派记为资源、灰烬派记为号召、逆记为祸根），而"谁话语权最大"由玩家的历史选择动态决定。任何预写脚本都会在第三次被玩家识破。

### 2.2 七个角色、七种腔调，也是 AI 的硬需求

同一句话落下，四个派系各自解读：维尔记为「神在试炼我们」，女王记为「上面那位撤资了」，灰烬记为「神厌弃我们，故当自焚以谢」，逆只说两个字：「看吧。」

这需要模型真正理解**立场差异**，而不是套模板。

### 2.3 AI 还承担了配图

每个回合结束后，旁侧模型把这一段剧情提炼成一句画面描述，再交给图像模型画一张，贴在消息下方。约束是硬的：**微距昆虫摄影 + 神永远不在画面里**（只能以画框外压下来的暗影与暖光暗示其存在）。六幕主图同样是 AI 生成的实拍风格大图。

> **一句话总结 AI 的价值**：在这款作品里，LLM 不是聊天框里的装饰，它是**全体 NPC + 唯一的对手 + 结局的合著者**。

## 三、核心玩法（对应「创新度」25%）

### 3.1 神没有技能栏、没有属性面板、没有神力值

玩家唯一的能力是**「随手」**。

你的一步＝它们的七级地震；一次呼吸＝飓风；随手一块饼干屑＝全巢三个月口粮；两袋超市打折的白砂糖＝几代人都耗不完的能源；一壶开水＝灭世的大洪水。

**这个设计选择的重量在于**：玩家不是故意作恶，他只是没有意识到自己在做什么。这比"扮演一个坏人"难写得多，也痛得多。

### 3.2 玩家可以选择不听、不理、走开——世界会用因果把他拉回来

你可以拒绝显灵。那么法阵会越来越亮、越来越频繁。你可以无视献祭。那么那一派会改而自我绝食。你可以不理会兵蚁统帅的请令——它会替你打了那场仗，并宣称是奉神谕。

**拒绝的代价是真实的，但主线锚点不会被跳过。** 这不是"玩家说了不算"，而是"世界不为玩家暂停"。

### 3.3 六幕与不可回避的一夜

| 幕 | 情境 | 你要面对的事 |
| --- | --- | --- |
| 一 · 显灵 | 台阶上的圆阵、缺笔的名字「张亮」 | 是否驻足、是否补全末笔 |
| 二 · 应许 | 两个小小的愿望：诛杀邻巢战士、赐一座山一样高的砂糖 | 你照做了（"毕竟……为什么不呢？"） |
| 三 · 狂热 | 糖是能源。繁荣、分裂、献祭、圣战 | 反驳不了任何一个教派 |
| 四 · 求爱者 | 提米求你让它成为"她眼中唯一的存在" | **你解决不了这个问题** |
| 五 · 覆巢 | 一个最平凡的「顺手」动作，或者你什么也没做 | **这一夜躲不掉** |
| 六 · 新世代 | 幸存者重建召唤仪式，经文第一页刻着戒律 | 你又路过那个台阶 |

**第五幕是刻意的强制锚点**，而且**结果固定、方法不限**：巢内除提米与缇尔外全灭，逆因独居巢外幸存；但那一击不必是开水——倒水、拖地、扫地、一脚，乃至「我什么都不做」都成立，祸因只能追到神身上。推进以提米那句「我他妈都许了什么愿啊」为**收束闸门**：台词不出现、或本幕停留超时，都会被强制推进。因为这场灾难必须由玩家亲手造成，这个游戏才成立。

### 3.4 六个结局

应验者、大洪水、沉默、聆听者、离场、造物主。终局由玩家过往所有选择的组合决定，无法穷举。**其中一个结局是：什么都没学会。**（当前版本四条可达，另两条因强制主线改动已停用，在 `endings.md` 中如实标注。）

## 四、产品形态与完成度（对应「完成度」25%）

### 4.1 已经是一个能从头玩到尾的产品

- **六幕主线完整**：`arc.json` 六幕齐全，含解锁关键词、回合门槛、本幕必发生事件、本幕基调与张力值
- **完整结局系统**：六种结局的条件写在 `endings.md` 并注入第六幕钩子，终局由状态变量 + 历次拍板留痕判定
- **七张角色卡**：维尔 / 蚁后 / 提米 / 缇尔 / 逆 / 灰烬 / 断颚，均为标准 `chara_card_v2` 格式
- **每回合 AI 插画**：正文先出、图后补，首屏用 `cover.svg` 兜底；固定幕画已移除——「这一刻生成的画面」比六张定妆图更贴
- **回合配图**：每回合现场生成一张，正文先出、图后补，不阻塞对话
- **存档 / 回档 / 世界线**：任意时刻存档，回档即整体替换，回档前自动留档
- **可观测**：`/metrics` 暴露 token 用量、延迟分位、provider 切换、记账成败

### 4.2 工程质量

- **75 个单元测试全过**；`tsc --noEmit` 严格模式零错误
- **零构建**：Node ≥ 22 原生运行 TypeScript，无打包步骤
- **运行时只依赖一个第三方包**（`ws`），其余全部手写：HTTP 服务、OpenAI 兼容客户端、上下文压缩、字符 n-gram 向量召回
- **零成本部署**：Vercel serverless，已上线

### 4.3 面对真实使用做过的加固（不是"能跑就行"）

- **空正文自愈**：主模型的思考链偶发吃光输出预算导致正文为空 → 入口处自动重试一次
- **防卡死**：第五幕即使玩家不输入任何相关词，也会在停留超时后强制推进（收束闸门 + 超时兜底）
- **移动端可用**：窄屏下手账折叠为抽屉，正文区实测 540px
- **可读性有据**：叙事区背后的虚化底纹下，正文最坏情况对比度 **14.1:1**（无障碍 AAA 标准为 7:1）

## 五、设计（对应「设计感」10%）

**美术方向：微距夜行。** 深蓝夜色打底，一盏钠灯的暖侧光，浮尘与暗角；叙事用衬线体，数据用等宽体。

一条铁律贯穿全部视觉：**神永远不在画面里**——画面里只有台阶、糖、水，和一个你从没低头看过的圆。

界面本身也是叙事的一部分：**每回合现场生成的那张插画**既贴在正文下方，也作为**虚化的背景底纹**铺在叙事区之后，让整个页面始终浸在当下这一刻的空气里；右侧「蚁巢手账」五个分页——主线 / 人物 / **经文** / 前情 / 世界线，玩家可以在那里读到刚刚出炉的、把自己拍成神的那一条经文。

## 六、与知乎的关系，以及合规（重要）

- **来源**：改编自知乎答主 **@狐狸** 的回答《克苏鲁可以被卑微的人类召唤，那人类可以被蚂蚁召唤吗？》。首屏、开场白与仓库 README 均显著标注原作者与原文链接。
- **边界**：第 1–5 幕忠于原著情节，第 6 幕为 AI 演绎补完；**未逐字复制原文长段**，游戏内标注出处并可跳回原回答。非原作者作品，不构成对原作者的权利主张。
- **用途声明**：本项目为知乎黑客松参赛演示，属**非商业性的衍生技术探索**；赛后如需使用请联系原作者。
- **内容边界**：故事涉及微小生命的死亡，但**不作血腥描写**；配图硬性禁止人体、血液、器官与侵入性操作，重量交给纸、灯与时间，不靠生理刺激。

## 七、技术实现

```
assets/campaigns/ants/     本作的全部内容（换一个目录即可换一个战役）
  card-ants.json           叙述者卡 + 内嵌运行规则 + 七个角色画像
  worldbook.json           世界设定（尺度换算 / 巢群社会 / 四派神学 / 经文规范）
  arc.json                 六幕主线（含强制锚点与 mustEvents）
  npcs/                    七张角色卡
  art/                     六幕配图 + 程序化生成脚本

src/                       运行时（确定性代码管状态，模型只管生成）
  harness/    上下文工程 / Agent 循环 / 记忆账本 / 决策卡 / 掷骰 / 世界线 / 回合配图
  director/   主线导演（关键词 + 回合门槛推进，支持强制锚点）
  roleplay/   角色卡 v1/v2 / PNG 内嵌卡 / 世界书混合激活
  llm/        手写 OpenAI 兼容客户端（多 provider 兜底、思维链剥离）
  server.ts   Web 服务（WebSocket + HTTP 兜底 + REST + /metrics）
web/index.html              前端（零构建单文件）
```

**架构主张**：**确定性代码管记忆与状态，模型只负责生成。**

上下文每一轮按预算重裁，只保留「人设 + 世界书 + 账本 → 剧情化摘要 → 近期原文」三层；超预算时由旁侧模型把最旧剧情压成保留专有名词与伏笔的前情提要。这条设计让长对话不越窗、不失忆。

## 九、后续规划

1. **知乎生态对接**：知乎 OAuth 授权入口与回调端点已落地（`/api/auth/zhihu/login`、`/api/auth/zhihu/callback`，授权后以知乎昵称署名）；下一步是用「知乎故事」内容池作为新战役的素材来源，并让玩家用自己的知乎身份署名「我是这个神的第几代信徒」
2. **战役包机制产品化**：运行时与内容完全解耦——换掉 `assets/campaigns/` 下的一个目录即可换一个故事，本作即以此结构开发。后续希望把它做成"任何人都能把一篇知乎回答变成一个游戏"的工具
3. **世代漂移的可视化**：把"同一条经文被历代改写"做成可对比的时间轴
