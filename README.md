# 全巢之力 · How Heavy the Whole Nest

> 一款基于**状态化 LLM Agent 运行时**的互动叙事游戏。
> 一个下班回家的普通人，被一窝蚂蚁奉为神——而这个神，从来不知道自己被信过。
>
> 改编自知乎答主 **@狐狸** 的回答《克苏鲁可以被卑微的人类召唤，那人类可以被蚂蚁召唤吗？》（65541 赞）。
> 第 1-5 幕忠于原著，第 6 幕「新世代」为 AI 演绎补完。

---

## 一、这是什么

你不是神。你只是一个拎着外卖、改了三遍方案、鞋底黏着口香糖的普通人。只是恰好，你家门口台阶的砖缝里，有一窝蚂蚁用亮晶晶的粉末画了个圆，用身体摆出了你的名字——缺了最后一笔。

玩家第一人称扮演这个"神"，输入动作、对话、念头。**神没有技能栏、没有属性面板、没有神力值**——他唯一的能力是"随手"，而随手会造成后果：你一步＝它们的一场七级地震，你拎回的两袋白砂糖＝它们几代人都耗不完的能源，你的一壶开水＝灭世的大洪水。

核心命题写在原著那句话里：**向古神许愿时，必须以百分之一万的谨慎态度审视愿望中的每一个字，因为你的愿望极有可能以一种扭曲的方式实现。**

## 二、六幕

| 幕 | 情境 | 原著锚点 |
| --- | --- | --- |
| 一 · 显灵 | 台阶上的圆阵、缺笔的名字、会发声的蚂蚁 | 蚂蚁开口请求神不要走 |
| 二 · 应许 | 两个小小的愿望：杀死邻巢的战士、赐一座山一样高的砂糖 | 你照做了（"毕竟……为什么不呢？"） |
| 三 · 狂热 | 糖是能源。蚁巢繁荣、分裂、献祭、圣战 | 教派成形，逆开始质疑 |
| 四 · 求爱者 | 提米求你让它成为"她眼中唯一的存在" | 你想到那个最省事的解法（这一幕是强制引信） |
| 五 · 开水 | 你先把提米和缇尔单独搁到一边，再把一壶开水倒进蚁穴 | 巢内除那两只外尽亡（逆独居巢外亦幸存），提米醒来面对满地族人尸体 |
| 六 · 新世代 | 幸存者重建召唤仪式，经文第一页刻着戒律 | 你又路过那个台阶 |

六个结局（`assets/campaigns/ants/endings.md`）：应验者、大洪水、沉默、聆听者、离场、造物主。其中**沉默 / 聆听者两条依赖"第五幕没有开水"，在开水改为强制主线锚点后已停用**，当前可触发的是应验者、大洪水、离场、造物主。

## 三、机制

详见 [`assets/campaigns/ants/MECHANICS.md`](assets/campaigns/ants/MECHANICS.md)。签名机制是**经文**：

> 蚂蚁如何记载神做过的事，与神实际做了什么，永远是两回事。旁侧记账模型把玩家的每个举动"翻译"成神学语言，并且**允许记歪**——随手踩死一只兵蚁＝「天罚」，倒下一袋糖＝「赐食」，搬家＝「神弃我们而去」。玩家可以随时打开账本，读到一条刚出炉的、把自己好心记成暴行的经文。

其余机制全部复用运行时已有能力，**默认零代码改动**：状态变量存记忆账本（`/state` 可见）、神谕卡复用决策卡、物理后果掷真随机、六幕推进由主线导演按关键词 + 回合门槛驱动（第四幕「求爱者」标记为 `autoAdvance` 强制锚点——它指向的是第五幕那壶开水，玩家不选也会发生）。

## 四、运行

前置：**Node.js ≥ 22**（原生运行 TypeScript，无需构建）。运行时只有 **一个第三方依赖 `ws`**（WebSocket 服务端）；LLM 客户端、世界书向量召回、PNG 角色卡解析等均为手写，其余全部使用 Node 内置能力。

```bash
npm run web        # 打开 http://127.0.0.1:7620
```

首次运行前需在 `.env` 里填 LLM 凭证（参考 `.env.example`）：

```
WANGDACHUI_API_BASE=...      # OpenAI 兼容端点
WANGDACHUI_API_KEY=...
WANGDACHUI_MODEL=...
```

**斜杠命令**：`/state` 看账本（信仰 / 巢群 / 怀疑 / 派系 / 经文）· `/phase` 看幕进度 · `/lore 词` 查世界书 · `/snap` 存档 · `/back` 回档。

**配图**：固定幕画已移除——界面由**每回合现场生成的那张插画**驱动（首屏用 `art/cover.svg` 兜底）。`art/` 下仅保留封面、人物图谱与纹样；`npm run art` 仍可重新生成全套。

**回合配图（AI 现场生成）**：每回合正文出完后，服务端会异步再做一件事——用旁侧模型把这段剧情提炼成一句画面描述（受"微距昆虫摄影 + 神不在画面里"的美术方向约束），再调图像模型画一张图，贴在消息下方。**正文先出、图后补，全程不阻塞对话**；图只走 UI，不进对话历史（否则 base64 会把上下文撑爆）。失败一律静默降级，只在服务端日志留一条 `illustration_fail`。

取图走 `GET /api/illustration?sid=X`，**直接回图片字节**（不是 JSON+base64——那会把体积撑大 33%，也逼近 Vercel 的 4.5MB 响应上限）；画面描述放在响应头 `X-Illustration-Prompt`。失败/关闭/超限回 204，前端静默撤掉占位。同一个回合的图会缓存 300 秒，翻回上一条不用重新下载。

延迟构成（实测）：**提炼约 2.4s + 出图约 6s**。注意出图受上游负载影响波动大，同一模型可能 6s 也可能 20s+；且网关忽略了 `size` 与 `output_format`，`quality=low` 只小 10%，所以单张固定约 800KB——**慢的时候多半是链路带宽，不是模型**。

配置（见 `.env.example`）：`WANGDACHUI_ILLUSTRATION=0` 可整体关闭；`WANGDACHUI_ILLUSTRATION_MODEL` 默认 `gemini-3.1-flash-lite-image`（实测约 6s/张、816KB，画质与 2.5 版同级，是最快最省的）；备选 `gemini-2.5-flash-image`（约 7–23s、1.6MB，**上游负载波动很大**）、`gemini-3.1-flash-image`（约 11s，画风偏 3D）。`flux` / `sd3.5-turbo` / `doubao-seedream` 在该网关实测 404/429/503，用不了。`WANGDACHUI_ILLUSTRATION_MAX` 是每会话出图上限（默认 30，防演示时额度被烧穿）。文字提炼那一头默认 `qwen-flash`（约 2.4s）——**别用思考型模型**（如 `gemini-3.8-flash`，它会把输出预算烧在思维链上，画面描述只剩十个字），也**出不了图**（纯文本模型，打图像接口直接 503）。

**界面**：`web/index.html`（零构建单文件）。美术方向是"微距夜行"——深蓝夜色打底，一盏钠灯的暖侧光，浮尘与暗角；叙事用衬线体，数据用等宽体。叙事区背后有一层**虚化底纹**——首屏用封面，之后跟随**每回合现场生成的那张插画**（图是这一刻的画面，比六张定妆图更贴）；右侧「蚁巢手账」五个分页：主线 / 人物 / **经文** / 前情 / 世界线。一条铁律贯穿视觉：**神永远不在画面里**——画面里只有台阶、糖、水，和一个你从没低头看过的圆。

移动端手账是从右侧滑出的抽屉（点顶栏「蚁巢手账」展开）。
